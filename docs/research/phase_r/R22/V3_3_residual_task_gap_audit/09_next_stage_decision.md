# 09｜下一阶段唯一建议

## 建议任务

**冻结 R22-V4 输出完整的确认性实验契约，暂不启动 CUDA。**

建议从 V3.2 已保留的确认性范围出发：30 个独立 seed × 速度 `{0.5, 2.5, 6.7}` m/s × SNR 20 dB × 时延 `{0, +4 ns}`，共 180 个 case。该范围只是方案输入，不构成用户运行授权；最终 case 数、统计单位和资源预算须在契约审查时冻结。

## 必须补齐的输出

1. 每个 case、每种方法保存全部十个处理周期的 Detection 与 truth lineage，使参数误差可在共同目标机会集上计算。
2. 保存 TrackManager 的逐帧 debug、关联 detection、航迹状态与 PIPE payload 字段来源，支持按仓库既有生产语义核验地速和目标保持。
3. 保存目标专属复数响应或足以计算目标幅度/相位保持的最小字段；不能用 CSI ROI 取代。
4. 将 Known correction 作为 evaluator-only 参考，估计器只读取其部署时可获得的 target-present 观测；paired OFF 若保留，只能作为单独标注的信息条件。
5. 若报告系统 Pfa，预先定义独立 H0 样本单位、虚警关联规则和统计方法；H0 不是 target-present 条件的替代。
6. 冻结四条件、方法信息条件、共同机会分母、缺失/不可评价处理、指标方向、统计分析和磁盘保留/清理账。

## 关键比较与退出门

对 A0、Current、Known、target-present deterministic estimate 做同输入配对比较，分别报告检测、共同成功参数误差、目标保持、航迹输出和可评价覆盖率。不得只在某方法成功子集上做全场排名；应同时披露各方法覆盖率和预定义共同机会结果。

若确定性方法在确认数据上持续接近 Known，且剩余参数/航迹误差没有任务重要性，则停止未知时延估计创新主张。若存在可重复残差，先比较更简单的确定性物理方法；只有当其仍无法解决稳定任务缺口时，才重新评估 AI 进入门。
